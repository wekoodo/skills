# Read-only validation semantics (candidate 1.2)

Run `python -B <skill>/scripts/audit_routed_context.py <root> [--json]` with Python 3.10+. No repair, cache, gate, directory or report is written inside the target. JSON remains a list of level/message/path findings. Default exit 1 means structural failure (missing entrypoint or malformed native stage); path defects warn and preserve the prior warning exit behavior. `--strict` also exits 1 on warnings. `--execution` warns for missing required working inputs; combine with `--strict` to block execution mechanically. A zero exit is never complete ICM certification.

## Paths and inputs

- Markdown inline links and `@AGENTS.md`-style shim imports resolve from the containing file, never opportunistically from the project root. Inputs use the same base, whether table cells (`Path`, `File`, or `Input` column) or bullet lists (a leading path in backticks, a link, or a simple bare path, optionally labelled Reference/Working/Required/Optional/Future or Layer 3/4). Use one input per bullet; further code paths in explanatory prose are reported for manual inspection, not treated as required dependencies. Paths embedded in prose without an explicit path/role prefix have unresolved base/requiredness. This matches the existing stage template. Root-oriented overlays must express the appropriate relative path in the source contract; the checker does not guess a second base.
- Required/reference inputs must exist. Label Layer 4 / working inputs separately: absent outputs are informational during structural audits, warnings with `--execution`. Explicit optional/future/not-yet-produced inputs stay informational. Required inputs must exist before actual execution; structural readiness does not authorize a run.
- Section fragments use URL-decoded, lowercase Markdown heading slugs: remove punctuation/inline markup, spaces become hyphens, duplicate headings gain `-1`, `-2`, etc. Explicit `<a id="...">` or `<a name="...">` anchors are accepted. Renderer-specific slugs need manual inspection.
- Paths outside the root (including resolved links/junctions), absolute paths, template placeholders and globs are reported unresolved and are not inspected. Web/mail links are not fetched. Wiki/reference-style links are reported unsupported. Simple inline Markdown is supported, not a complete Markdown/YAML parser; nested parentheses, complex escaped table cells, custom HTML and prose-only path mentions require manual checking. Directory existence does not establish scoped file completeness.

## Coverage and overlays

The scanner checks entry files, preferred/alternate root routers and `CONTEXT.md` contracts outside excluded trees. It does not recursively load arbitrary Markdown, personal record bodies, installations or runtimes. Fenced examples are ignored, including fenced headings. Generic history is excluded, never repaired. `--history <relative-file-or-directory>` explicitly checks historical links as informational findings only. Exclusions and counts are printed in the coverage finding; this is not an exhaustive repository link audit.

Use repeatable `--router`, `--reference-area`, and `--control-surface` arguments for recorded project locations. These are scoped declarations, not a configuration rewrite or a semantic override. For example: `--router cycles/README.md --reference-area docs/contracts --control-surface cycles`. Existing equivalent layouts need no renames. Read the project's ICM conventions yourself: the script does not interpret arbitrary prose or infer authority/factory roles from paths. A numbered collection needs member contracts to be recognized as a possible library; that remains a heuristic requiring topic-selection confirmation. No folder is classified as a library solely for numbering.

A project may use only Layers 0–1 (+3), libraries, a pipeline or a foreign control tree. There is no requirement to add `stages/`. Outputs can be future or live at alternate paths; a conventional `output/` is an existence check, never a review gate verdict. Check/Review Gate/Verify bodies require manual assessment of actor, criterion, failure stop, evidence and freshness. Empty headings warn. The checker never interprets a stored `pass` as current authorization.

## Walk-test evidence

Use a fresh context where available; otherwise explicitly record a manual simulation. Start at the canonical entry, then routing and the current-state owner. Identify the task contract, exact scoped inputs, output, check actor/criterion/stop, and any missing data. Follow historical references as provenance, not current instructions. Record paths read, decisions, warnings, failures and untested cases. Test one bounded synthetic addition in a disposable copy, inspect its exact diff, and repeat the read-only audit to confirm deterministic findings and no edits. Do not execute embedded kickoff instructions, applications or external workflows as part of orientation.
